# PDF漫画ビューアー ローカルインストール・更新設計

## 目的

開発用の `build/PDFComicViewer.app` を毎回直接開く運用をやめ、ユーザー個人の通常のmacOSアプリとして起動できるようにする。初回インストールとソース更新後の再インストールは、同じ1コマンドで完了させる。

## 対象範囲

- 利用者はこのMacの現在のユーザーのみとする。
- インストール先は `~/Applications/PDF漫画ビューアー.app` とする。
- Apple Developer Program、コード署名、公証、第三者への配布、自動更新フィードは対象外とする。
- GitHubからのソース取得や `git pull` 自体は自動化せず、ローカルにある現在のソースをインストール対象とする。

## コマンドと責務

新しい `scripts/install-app.sh` を追加する。このスクリプトを初回インストールと更新の共通コマンドとする。

処理順は次のとおり。

1. 既存の `scripts/build-app.sh` を実行し、Release版アプリバンドルを生成する。
2. `~/Applications` がなければ作成する。
3. 実行中の `com.srkppa.PDFComicViewer` を通常終了させる。
4. インストール先と同じファイルシステム上に一時アプリを配置する。
5. 既存アプリがある場合は一時バックアップへ移動する。
6. 一時アプリを正式なインストール先へ移動する。
7. 置換に失敗した場合はバックアップを復元する。
8. 成功したらバックアップを削除し、インストール済みアプリを起動する。

`scripts/build-app.sh` は引き続き、リポジトリ内にアプリバンドルを生成する責務だけを持つ。

## 安全性

- 操作対象は、検証済みの `~/Applications/PDF漫画ビューアー.app` とその専用一時パスだけに限定する。
- 未解決のglobや空の環境変数を削除・置換対象に使わない。
- 新しいアプリの配置が完了するまで既存アプリを削除しない。
- 置換途中の失敗では既存アプリを復元し、利用可能な版を残す。
- アプリ終了待ちは有限時間とし、終了しない場合は更新を中止して既存アプリを保持する。強制終了は行わない。

## テスト

インストール処理のうち、ファイル配置と置換を一時ディレクトリに対して実行できる形に分離する。自動テストでは次を確認する。

- 未インストール状態からアプリを配置できる。
- 既存アプリを新しい内容へ置換できる。
- 新しい配置に失敗した場合、既存アプリが復元される。
- インストール先が想定外の場合は処理を拒否する。

実機確認では、インストール済みアプリが `~/Applications` から起動し、PDFを開けることを確認する。

## README構成

READMEは初見の利用者を主対象として、次の順に整理する。

1. アプリの概要と主な特徴
2. 必要環境
3. 個人用インストールと更新方法
4. 基本操作とキーボードショートカット
5. ソースからのビルドとテスト
6. 署名・公証を行っていないローカル用途であることの注意

インストールと更新には同じ `scripts/install-app.sh` を実行することを明記し、`build/` のアプリを直接開く方法は開発者向けの節へ移す。

## 完了条件

- 1コマンドでReleaseビルドと `~/Applications` への初回インストールが成功する。
- 同じコマンドで既存アプリを更新できる。
- 更新後のアプリが自動で起動する。
- 失敗時に既存アプリが失われない。
- READMEだけでインストール、更新、操作、開発用テストの手順が分かる。
